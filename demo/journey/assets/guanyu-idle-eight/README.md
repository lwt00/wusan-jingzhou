# 关羽 · 待机八帧（guanyu-idle-eight）

程序化切分与对齐，仅用于观察这组素材的循环节奏。**尚未接入 Demo**，不读写存档，不影响任何既有流程。

## 来源与假设

- 原始素材：剪贴板图片 `clipboard-2026-10-13T14-25-18-507Z-2f1c8385.jpg`，1536×1024 JPG，背景为纯白 255。原图另存于本目录 `raw/` 之外，未改动。
- ⚠️ **网格与帧序为假设**：按 4 列 × 2 行等分（单元格 384×512）、帧序按阅读方向（上排 1-2-3-4 → 下排 5-6-7-8）处理。程序化校验支持"等分"这个假设（切割点全部落在谷底），但**帧序是否如此需要人工确认**；若原图顺序不同，动作会错乱。
- ⚠️ 本文档所有结论来自程序化测量（像素统计），**不包含肉眼目视核对**。

## 处理链路

1. **等分切格**：验证切割点是否落在内容剖面的谷底。
2. **去白底**：从画布边界漫灌非内容区域（`flood from border`），只清除与外部连通的白底，**内部白色高光不会被吞掉**；alpha 经 0.8px 高斯模糊保留软边。
3. **去跨格杂质**：取四连通最大连通域为主体，丢弃其余连通域。
4. **对齐输出**：垂直按**脚底**对齐，水平按**头肩部重心**对齐（躯干稳定，披风可自由飘动）。

## 结论与建议

- 这组帧**能成立为待机循环**：8 帧姿态各不相同、首尾闭合自然、基线可对齐，没有硬性缺陷。
- 帧间差异偏大（0.10–0.17），说明动作幅度不小，8 FPS 下会显得偏"抖"。**建议先试 6 FPS**，再决定 8 还是 4。
- 水平方向主体重心在格内 x≈250–275 间浮动（极差 25px），已按头肩轴对齐消解；若接入后仍有左右晃动，需改用躯干中轴重新对齐。
- 尚未判断这组能否作为**行走**使用——需要腿部姿态的专项分析（接触/下沉/通过/上升四个关键姿态），本次未做。
