# 六帧关羽骑马测试素材

原图 source-six.png：1536×1024，RGBA；alpha 范围0～254，833707个完全透明像素，是真实透明图，不是黑底或棋盘底。原图留存，未覆盖用户素材。

## 分离检查

不能等分裁切：x=512/1024竖线穿过部分主体；alpha>8的连通轮廓能辨认六个独立主体，按从上到下、从左到右排序分离。透明区有极低 alpha 底噪，alpha>0时两个上排主体会被这些底噪连接，不是角色互相粘连。

导出时采用独立轮廓，在其周围保留2像素软边，同时排除其他主体；去除不属于角色的极低透明背景噪点。未补画、重绘刀具或改动关羽形象。各帧使用统一640×512透明画布，保持原比例，仅依据人工检查的躯干参考点平移。参考点及偏移见 audit.json。

- 马头、刀刃、披风、马蹄跨越等分网格，但主体轮廓分离后没有相邻角色混入。
- 六帧均可辨认持刀手握住刀柄，刀刃保持左侧；没有上一版的左右换位。单侧插画无法严格核实解剖学左右手，不能额外保证“右手”准确。
- 第六帧最右马蹄轮廓触及原图最右边缘（只剩极少抗锯齿像素余量），没有看到大块主体丢失，但正式素材应重新提供留白充足的原帧，避免边缘完整性风险。
- 人物与马匹大小基本接近，但原画中头冠/衣物/刀刃等形状仍有轻微变化。统一画布和比例不能消除原画形变。
- 地面参考线y=486，按躯干对齐后保留腾空姿态，不能简单把每帧最低脚拉到同一高度，否则马身会上下跳。

## 当前优化：8 / 10 / 12 FPS 与稳定补偿

原始六张PNG及原图集保持不变（SHA-256校验一致）。当前测试默认10 FPS，可在赶路右上角切换8/10/12 FPS、开关稳定补偿；也可打开 `riding-compare.html` 并排观察、暂停、同步重播。切换速度只改变后续相位增长，保留当前相位，不因切速瞬间跳帧。

补偿表见 travel-config.js 的 WusanRidingTuning.offsets，单位为原画像素：仅小幅横/纵向平移上半身稳定参考，不改角色比例，不拉伸，也不叠加两帧。画面地面/角色容器与整体缩放不变；腾空姿态保留。该补偿不等于精确锁定所有马蹄，仍需源帧正确的接地周期。

结论：
- 建议以10 FPS为观察默认值，是8 FPS较明显的离散停顿与12 FPS较急节奏之间的折中。每周期分别0.75/0.6/0.5秒，FPS不增加真实中间动作。
- 1→2的腿部轮廓变化较大；2→3的刀具区域变化较大。原帧透明预乘RGB区域差异记录在 tuning-audit.json，属于图形差异指标，不是奔跑生物力学评分。
- 6→1仍存在刀具、衣物与腿部姿态差异。整体参考位置更稳定，但循环不能视为完全自然。
- 保留01→06顺序：现有六张图不能可靠对应一个严格完整的奔跑相位周期，仅重排容易把局部顺畅变成其他位置的跳变。
- 代码可以修正切速跳帧、整体位置偏差、固定缩放、计时与循环；关节运动连续性、马蹄接地/腾空时序、刀具与披风形变、首尾过渡需要重新制作帧或增加真正中间帧。

此节覆盖早期固定8 FPS的操作说明；仍只在骑马测试模式生效，默认游戏与其他人物不变。
